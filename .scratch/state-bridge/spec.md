## Problem Statement

When migrating multi-file Python client codebases from `requests` to `httpx`, developers and coding agents encounter a deceptive failure mode we term **The Stateful False-Friend Paradox**: `requests` (`2.34.2`) and `httpx` (`0.28.1`) share 88.9% identical top-level function names (`get`, `post`, `request`, etc.), 83.3% identical `Session`/`Client` method names, and high 256-dimensional embedding cosine similarity (`>0.85`), yet they diverge silently across multi-step stateful HTTP interactions (redirect following defaults `allow_redirects=True` vs `follow_redirects=False`, cross-origin 301/302/303 `Authorization` and method preservation, cookie jar scoping across hops, streaming response lifecycle `stream=True` vs `Client.stream()` + `.read()`/`.iter_bytes()`, and client-level vs request-level configuration/`HTTPStatusError` handling). When session initialization, authentication injection, request dispatch, redirect handling, and stream cleanup are split across multiple functions in a repository's call graph, single-function AST codemods, function-local LLM prompts, and embedding-nearest-neighbor retrieval fail to observe upstream and downstream stateful invariants, producing code that compiles and passes single-step smoke checks while failing multi-step protocol execution.

## Solution

We introduce **StateBridge × TwinAPI**, an empirical research study, reproducible benchmark (`StateBridge-Bench`), zero-dependency Google ADK Skill (`skills/state-bridge/SKILL.md`), and single-file interactive Explorer (`explorer/index.html`) built for the Kaggle **Google — The Gemma 4 Developer Agent Paper Track**:

1. **Part 1 — `TwinAPI` Stateful False-Friend Audit**: Quantifies lexical edit distance, parameter-masked signature isomorphism, and 256-d embedding cosine similarity across `requests ↔ httpx` API pairs, proving that surface and dense-embedding alignment (`>0.85`) systematically fails to separate behaviorally equivalent twins from stateful false friends across five multi-step divergence families.
2. **Part 2 — `StateBridge-Bench` & 5-Arm Controlled Ablation on Real `Gemma-4-31B-IT` and `Gemma-4-26B-A4B-IT`**: Evaluates 30 multi-file, multi-step HTTP client workflows (6 workflows × 5 divergence families) against a deterministic local Loopback HTTP State Machine (`127.0.0.1:0`) across five orthogonal arms:
   - `Arm 1`: Deterministic AST Codemod baseline (`import httpx`, `Session`→`Client`, local kwarg mapping).
   - `Arm 2`: `Gemma 4` + Target Function Only (+ static API diff cheat-sheet).
   - `Arm 3`: `Gemma 4` + Top-$K$ Repository Functions retrieved by 256-d `TwinAPI` Embedding similarity.
   - `Arm 4`: `Gemma 4` + `StateBridge` True Cross-Function Stateful Call-Graph Slice (1–2 hop callers/callees along the `Session`/`Client`/`Response` flow).
   - `Arm 5`: `Gemma 4` + Equal-Token Unrelated Repository Function Slice (negative structural control isolating true graph connectivity from context length).
3. **Part 3 — Dual-Track 15-Second Judge Reproducibility & Single-Source-of-Truth (SSOT) Pipeline**: All real `Gemma-4-31B-IT` and `Gemma-4-26B-A4B-IT` generations (with `<thought>` reasoning traces preserved and accounted) are frozen in `artifacts/raw_llm_generations.jsonl`. Running the CLI or Kaggle Notebook (`Run All`) executes all frozen candidate programs live against the local Loopback HTTP State Machine in `< 15 seconds` without requiring API keys or GPUs, compiling `artifacts/metrics_ssot.json` and `artifacts/explorer_bundle.json` to populate the `<= 3,000`-word Kaggle Writeup, arXiv PDF, Notebook, and interactive HTML Explorer with zero cross-surface number drift.

## Implementation Decisions

- **Single Canonical Stdlib Kernel (`skills/state-bridge/scripts/statebridge_core.py`)**: Implement the cross-file AST call-graph slicer, deterministic AST codemod (`Arm 1`), `canonicalize_exchange()` normalizer, `evaluate_trace_equivalence()` comparator, `ThreadingHTTPServer` (`127.0.0.1:0`) multi-step Loopback HTTP state machine, and CLI (`scan`, `verify`, `reproduce-paper`, `selftest`) in a single zero-third-party-dependency Python standard library module shared by the ADK Skill, benchmark runner, and Kaggle Notebook `[user: "可以"]`
- **`TwinAPI` Stateful False-Friend Audit & Precomputed 256-d Embeddings**: Build the `TwinAPI` mapping catalog across `requests==2.34.2` and `httpx==0.28.1` public and session/client APIs, computing normalized edit distance, parameter-masked signature isomorphism, and 256-d embeddings (via `google/models/gemini-embedding-001` with `dimensions=256` frozen at build time into `artifacts/twinapi_embeddings_256d.json` so runtime execution requires zero network calls), and annotating each pair with its multi-step divergence family `[user: "1a, 2a, 3a"]`
- **30-Task Multi-File `StateBridge-Bench` Across 5 Divergence Families**: Construct 30 clean-room, Apache-2.0 multi-file Python client workflows (6 workflows × 5 families: `F1_REDIRECT_FOLLOW_DEFAULT`, `F2_CROSS_ORIGIN_AUTH_STRIP`, `F3_COOKIE_JAR_SCOPING`, `F4_STREAM_CONTEXT_LIFECYCLE`, `F5_CLIENT_INIT_AND_STATUS_ERROR`), where each workflow distributes client initialization, request preparation/auth, multi-step execution (2–4 HTTP hops), and response/error handling across 3–4 functions plus 2–3 unrelated distractor functions in the same module tree `[evidence: .scratch/state-bridge/brainstorm-review-2026-11-09.md#Seat-4-High-5]`
- **HTTP Exchange Canonicalization & Anti-Cheat AST Gate**: Before comparing reference (`requests`) and candidate (`httpx`) HTTP step traces, normalize each recorded step via `canonicalize_exchange()`: uppercase HTTP method, parse query strings via `parse_qsl`, lowercase header keys, strip transport-default headers (`user-agent`, `host`, `connection`, `accept-encoding`, `content-length`), parse `cookie` headers into key-value dicts, parse `application/json` bodies via `json.loads` to ignore whitespace differences (`b'{"x": 1}'` vs `b'{"x":1}'`), and compare exception outcomes by error class family and HTTP status code rather than `str(exc)` text. Prior to execution, scan candidate ASTs and reject any code containing `import requests`, `from requests`, or `urllib.request` as `CHEAT_RESIDUAL_REQUESTS` `[evidence: .scratch/state-bridge/brainstorm-review-2026-11-09.md#Seat-5-Blocker-1]`
- **Real Dual-Model Inference Protocol (`Gemma-4-31B-IT` & `Gemma-4-26B-A4B-IT`)**: Execute all LLM arms (`Arm 2`, `Arm 3`, `Arm 4`, `Arm 5`) against `google/models/gemma-4-31b-it` and `google/models/gemma-4-26b-a4b-it` with `temperature=0.0`, `max_tokens=8192`, `max_concurrency=2`, and `min_interval=2.0s` (~15 RPM to prevent Magpie provider-wide 429 cooldowns). Strip `<thought>[\s\S]*?</thought>` blocks before extracting Python code fences, record both `thought_chars`/`reasoning_tokens` and `visible_completion_tokens`, and atomically append each completed call (`os.fsync`) to `artifacts/raw_llm_generations.jsonl` for checkpoint resume `[evidence: .scratch/state-bridge/brainstorm-review-2026-11-09.md#Seat-2-Blocker-1]`
- **Zero-Escape Subprocess Sandbox (`sys.addaudithook` + Ephemeral Port + Process Group Cleanup)**: Execute each workflow evaluation in an isolated `tempfile.TemporaryDirectory()` with `HTTP_PROXY=""`, `HTTPS_PROXY=""`, `NO_PROXY="*"`, a CPython `sys.addaudithook` that raises `RuntimeError("NON_LOOPBACK_EGRESS_BLOCKED")` on any socket connection outside `{"127.0.0.1", "::1", "localhost"}`, an ephemeral port (`127.0.0.1:0`) on `ThreadingHTTPServer` with `2.0s` socket timeout, and `subprocess.Popen(..., start_new_session=True)` with `os.killpg` cleanup on a `3.0s` per-workflow timeout `[evidence: .scratch/state-bridge/brainstorm-review-2026-11-09.md#Seat-4-Blocker-1]`
- **Single-File Self-Contained Interactive HTML Explorer (`explorer/index.html`)**: Build a zero-build-step interactive Explorer (`explorer/index.html`) driven by `artifacts/explorer_bundle.json` that presents the `TwinAPI` Stateful False-Friend Map and a 1-vs-1 Diff Split View (`Arm 4` vs `Arm 3`/`Arm 5`/`Arm 1`/`Arm 2`), auto-collapsing matching HTTP steps, highlighting the `First-Divergence Step` field diff, and supporting `#case=<id>&arm=<arm>&model=<model>` URL hash deep-linking `[user: "1a, 2a, 3a"]`
- **SSOT Surface Compilation & Consistency Gate (`scripts/build_ssot.py` & `scripts/verify_ssot_consistency.py`)**: Compile `artifacts/metrics_ssot.json` from live Loopback replay of `artifacts/raw_llm_generations.jsonl`, automatically generate `writeup/KAGGLE_WRITEUP.md` (verified `<= 3,000` words), `paper/paper.md` + `paper/paper.pdf`, `notebooks/reproduce_statebridge.ipynb` (executed via `jupyter nbconvert --execute` or script runner), and `explorer/index.html`, and verify 100% numeric agreement across all surfaces via `scripts/verify_ssot_consistency.py` `[evidence: .scratch/state-bridge/brainstorm-review-2026-11-09.md#Seat-6-Blocker-1]`

## Testing Decisions

- **What makes a good test**: Tests exercise only the two confirmed public seams (`skills/state-bridge/scripts/statebridge_core.py` and `scripts/build_ssot.py` + `scripts/verify_ssot_consistency.py`) through real execution and real local loopback sockets without mocking internal helpers.
- **Modules under test**:
  1. `skills/state-bridge/scripts/statebridge_core.py` (canonicalizer, trace equivalence oracle, AST anti-cheat gate, 5-arm context slicer, Loopback HTTP state machine sandbox, and CLI verbs `selftest` / `scan` / `verify` / `reproduce-paper`).
  2. `scripts/build_ssot.py` and `scripts/verify_ssot_consistency.py` (end-to-end replay, statistical test calculation, surface rendering, word-count check `<= 3,000` words, and cross-surface numeric consistency check).
- **Prior art**: Standard Python `unittest` / `pytest` + `hypothesis` (or pure-stdlib property generator) testing against real `127.0.0.1:0` `ThreadingHTTPServer` sockets.
- **Conditional PBT Specification (Shapes 1, 3, and 4 in `statebridge_core.py`)**:
  - **Applicability domain**: Multi-step HTTP exchange traces (1–5 steps, methods `GET|POST|PUT|DELETE`, arbitrary JSON dicts, query param pairs, header casing permutations, cookie key-value maps, and transport-default headers) and multi-function Python AST call graphs.
  - **Mapped Invariants (`P1..P4`)**:
    - **`P1 (Canonicalization Idempotence & Whitespace/Case Invariance)`**: For any valid HTTP exchange trace $T$, `canonicalize_exchange(canonicalize_exchange(T)) == canonicalize_exchange(T)`, and permuting JSON whitespace (`separators=(", ", ": ")` vs `(",", ":")`), header casing, cookie pair order, or default `User-Agent`/`Content-Length` headers yields an identical canonical trace.
    - **`P2 (Trace Equivalence Reflexivity & First-Divergence Exactness)`**: For any canonical trace $T$ of length $N \ge 1$, `evaluate_trace_equivalence(T, T)` returns `outcome_category == "PASS_EQUIVALENT"` and `first_divergence_step is None`; when step $k \in \{1..N\}$ is mutated on a semantic field (method, path, non-default header, cookie value, JSON payload value, or status error code) while steps $1..k-1$ remain unchanged, `evaluate_trace_equivalence(T, T')` deterministically returns `outcome_category == "STEP_K_WIRE_DIVERGENCE"` and `first_divergence_step == k`.
    - **`P3 (AST Anti-Cheat Soundness & Completeness)`**: Any candidate Python AST containing direct or aliased imports of `requests` or `urllib.request` (`import requests`, `import requests as r`, `from requests import Session`, `__import__("requests")`) is deterministically classified as `CHEAT_RESIDUAL_REQUESTS` before socket execution, whereas valid `httpx`-only ASTs pass the anti-cheat gate.
    - **`P4 (Arm 4 vs Arm 5 Context Budget Parity)`**: For any multi-file workflow task, the token/character budget of non-target functions selected in `Arm 5 (Equal-Token Unrelated Slice)` matches `Arm 4 (True Call-Graph Slice)` within the declared tolerance bound while sharing zero direct stateful call edges with the target function.
  - **Independent Oracle boundary**: The PBT oracle constructs ground-truth canonical dicts and exact divergence indices $k$ directly from the generated structural inputs prior to serialization into raw HTTP wire format, independent of `statebridge_core.py`'s parser implementation.

## Out of Scope

- Fine-tuning or LoRA weight training of Gemma 4 models (all experiments evaluate inference-time graph and embedding representations on `Gemma-4-31B-IT` and `Gemma-4-26B-A4B-IT`).
- External internet requests, live third-party HTTP APIs, or non-deterministic network timeouts during benchmark evaluation.
- Heavy frontend build toolchains (Webpack/Next.js server runtime) for the interactive Explorer (`explorer/index.html` is a single self-contained HTML/CSS/JS artifact).
